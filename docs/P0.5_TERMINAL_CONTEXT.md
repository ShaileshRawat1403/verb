# P0.5 Terminal Context Contract

## Status

Phase 1 was adapter-owned, metadata-only context with no command tracking.

Two things have shipped since and are now part of this contract:

1. **Shell Awareness P0** — Verb writes its own shell-integration script into the CLI userland and
   parses the OSC 7 / OSC 633 markers it emits, giving advisory command lifecycle metadata.
2. **Foundation Truth Step 1** — the shell's live working directory is exposed as its own signal,
   separate from the directory the session was launched in.

The "no OSC parsing" prohibition below has been deliberately lifted for those markers only. Every
other boundary in this document still stands, unchanged.

## Available context

`TerminalRuntimeAdapter.terminalContextState` exposes only:

- `UNAVAILABLE` or `SESSION_ONLY` capability;
- an ephemeral Termux session identifier when a live session is available;
- alternate-screen state: `ACTIVE`, `INACTIVE`, or `UNKNOWN`.

The production Termux adapter reads alternate-screen state directly from the emulator while
handling a screen update. It does not infer state from transcript text.

### Shell integration (advisory)

`TerminalRuntimeAdapter.commandHistory` and `shellIntegrationActive` expose bounded, session-local,
non-persistent command lifecycle records built from OSC 633 markers, plus OSC 7 for the working
directory. The markers come from a Verb-authored script (`TermuxBootstrapInstaller`), are parsed by
`ShellIntegrationParser`, and are turned into records by `CommandExecutionTracker`.

Constraints that make this safe to expose:

- **Advisory, never a security signal.** Any process writing to the PTY can emit the same bytes.
  Markers must never gate execution, approval, or trust decisions.
- **Structurally consumed.** Markers are read from the emulator's OSC handler, never scraped from
  screen or transcript text. A malformed or oversized payload parses to `null` and is dropped.
- **Bounded and non-persistent.** History is capped at `CommandExecutionTracker.MAX_HISTORY` records
  in memory, never written to disk, never forwarded to any AI provider.
- **Metadata only.** Records hold command text, exit code, duration, and working directory. They
  never hold command output or transcript text.
- **Redacted.** Command text passes through `SecretGuard` before it reaches a record, and is never
  written to logcat.

### Working directory

Two separate facts, never collapsed into one:

- `launchWorkingDirectory: File` — the **host** directory the session's process was launched in.
  Static for the life of a session. It is not, and must not be presented as, where the shell is.
- `currentWorkingDirectory: StateFlow<TerminalWorkingDirectory?>` — the shell's own directory,
  sourced only from OSC 7. `null` means unknown.

`TerminalWorkingDirectory` carries `guestPath` (what the shell reported) and `hostPath` (non-null
only when `GuestPathMapper` could translate it through an allowlisted bind). Guest and host paths
are different namespaces: `File(guestPath)` must never be constructed directly.

`currentWorkingDirectory` is `null`:

- before the first OSC 7 marker of a session;
- after a session ends, restarts, or is reconfigured;
- for the entire life of an Agent Runtime session, whose rootfs ships no integration script;
- wherever the user's shell is not the integrated interactive bash.

`null` must be surfaced as unknown. It is never a cue to fall back to `launchWorkingDirectory`.

It updates once per shell prompt, so during a long-running command it holds the directory that
command started in.

## Explicitly unavailable

The current adapter boundary still cannot reliably provide:

- process inventory or lifecycle for anything inside the guest (only the PTY leader is visible);
- confirmation that an interrupt (Ctrl-C) took effect;
- command-associated output;
- Git, repository, or file-change state;
- session persistence or reattach across app process death;
- any agent-level state, including whether an agent is waiting on the user.

No feature may infer these signals from prompts, screen snapshots, historical transcript text,
or shell-output regular expressions. Where a signal is genuinely unavailable it must be modelled
as unknown, not approximated.

## Privacy boundary

`SecretGuard.redactKnownSensitiveText()` removes an entire value matching a known local secret
pattern. It is a prerequisite for bounded context, not permission to retain arbitrary terminal data.

- Command output is never persisted as part of command tracking.
- Command lifecycle records are never forwarded to any AI provider.
- Unredacted terminal history must not be persisted or forwarded for remote analysis.
- The bounded transcript snapshot Room stores per submitted command is redacted first, and stores
  the working directory as the shell's guest path or `null` — never a substituted launch directory.

## Frozen foundation

Work in this area must not alter Termux PTY behavior, terminal rendering, selection, or JNI/NDK
code.

The one deliberate exception, already taken and not to be widened without review: the vendored
emulator carries a minimal patch adding OSC 7/633 case labels that forward the raw payload to
`TerminalSessionClient.onShellIntegrationOsc`, and Verb writes its own shell-integration script into
the guest. Markers are still never parsed at the screen-transcript boundary.

## Required device evidence before a later event-spine phase

The following are `NOT_RUN` until verified on a real Android session:

1. Alternate-screen transitions using an installed full-screen program, or a controlled terminal
   mode-sequence test on a development device.
2. Session state and context reset after the shell exits.
3. Behavior during high-volume output without UI stalls or inferred command boundaries.
4. Input-path coverage for keyboard, paste, IME, control keys, and direct session writes.
5. OSC 7/633 markers actually firing in the on-device guest shell, including the handshake, the
   working directory after a `cd`, and `D;130` after an interrupt.

Any later raw protocol listener requires a separately reviewed, narrowly scoped feasibility spike.
