# P0.5 Terminal Context Contract

## Status

Phase 1 is adapter-owned, metadata-only context. It does not establish command tracking.

## Available context

`TerminalRuntimeAdapter.terminalContextState` exposes only:

- `UNAVAILABLE` or `SESSION_ONLY` capability;
- an ephemeral Termux session identifier when a live session is available;
- alternate-screen state: `ACTIVE`, `INACTIVE`, or `UNKNOWN`.

The production Termux adapter reads alternate-screen state directly from the emulator while
handling a screen update. It does not infer state from transcript text.

## Explicitly unavailable

The current adapter boundary cannot reliably provide:

- command start or finish boundaries;
- per-command exit codes;
- dynamic shell working directory;
- command-associated output;
- complete keyboard, paste, IME, or control-key input.

No feature may infer these signals from prompts, screen snapshots, historical transcript text,
or shell-output regular expressions.

## Privacy boundary

`SecretGuard.redactKnownSensitiveText()` removes an entire value matching a known local secret
pattern. It is a prerequisite for future bounded context, not permission to retain arbitrary
terminal data. Phase 1 context contains no command or output payloads.

Unredacted terminal history must not be persisted or forwarded for remote analysis.

## Frozen foundation

P0.5 must not alter Termux PTY behavior, terminal rendering, selection, JNI/NDK code, or shell
configuration. In particular, it must not inject shell hooks, rewrite prompts, or parse OSC
markers at the screen-transcript boundary.

## Required device evidence before a later event-spine phase

The following are `NOT_RUN` until verified on a real Android Termux session:

1. Alternate-screen transitions using an installed full-screen program, or a controlled terminal
   mode-sequence test on a development device.
2. Session state and context reset after the root shell exits.
3. Behavior during high-volume output without UI stalls or inferred command boundaries.
4. Input-path coverage for keyboard, paste, IME, control keys, and direct session writes.

Any later raw protocol listener requires a separately reviewed, narrowly scoped feasibility spike.
